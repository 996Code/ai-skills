# 审查机制详细规则

> SKILL.md阶段4.8和阶段5的详细规则，审查/审校时按需加载。

## 4.8 逐章5视角审查机制（中篇/长篇）

每章写完后，启动5个读者视角进行审查。

**⚠️ 审查方式：主对话逐视角自审（唯一方式）**

蛋蛋在主对话中逐个输出5个视角的审查结果，每次只输出1个视角，控制单次输出长度。

**禁止使用delegate_task做审查**——原因：①API单次输出长度限制，子代理写审查文件时输出太长必被截断；②审查需要全文上下文理解；③蛋蛋自己做审查质量更可控。

**禁止使用execute_code做审查**——同样会被API截断。

**⚠️ 审查产出铁律：审查结果必须落文件+提交git**

1. **每个视角写独立文件**：`reviews/per-chapter/ch-[N]/逻辑侦探.md`、`情感猎手.md` 等5个文件。**简化选项**：如果5个视角审查均无P0/P1问题（全部🟢P2或✅），可以只写 `review.md` 汇总文件，不写5个独立文件——省时省力。有P0/P1问题时仍需5个独立文件+汇总。
2. **汇总写review.md**：`reviews/per-chapter/ch-[N]/review.md`，包含5视角评分表+问题汇总+修复记录+审查结论
3. **提交到git**：审查文件和正文修改一起commit

**主对话逐视角自审流程**：

```
蛋蛋在主对话中逐个输出5个视角审查（每次1个视角，控制输出长度）：
  ├─ 逻辑侦探 → 直接在对话中输出审查结果 → 写入 逻辑侦探.md
  ├─ 情感猎手 → 直接在对话中输出审查结果 → 写入 情感猎手.md
  ├─ 风格鉴定师 → 直接在对话中输出审查结果 → 写入 风格鉴定师.md
  ├─ 结构建筑师 → 直接在对话中输出审查结果 → 写入 结构建筑师.md
  └─ 世界观守门人 → 直接在对话中输出审查结果 → 写入 世界观守门人.md

蛋蛋汇总：
  └─ 将5个视角审查结果写入 reviews/per-chapter/ch-[N]/review.md（最终档案）
  └─ git add + commit 审查文件和正文修改
```

**⚠️ 已知问题：API单次输出长度限制**

根因：模型生成较长的工具调用参数时，流式传输被截断，Hermes将残缺参数替换为空对象`{}`，导致write_file写入空文件或execute_code执行失败。

**规避方法**：
1. **审查不用delegate_task** — 用主对话逐视角自审
2. **审查不用execute_code** — 同样会被截断
3. **每次只输出1个视角** — 控制单次输出长度
4. **多replace操作写Python脚本** — `write_file('/tmp/fix.py', script_content)` → `terminal('python3 /tmp/fix.py')`
5. **read_file有去重机制** — 第二次读同一文件返回bool而非内容，需用terminal `cat`或缓存首次读取结果

**审查记忆传递机制**：

1. **审查档案文件**：每章审查完成后，生成 `reviews/per-chapter/ch-[N]/review.md`，包含：
   - 5个视角各自的审查意见
   - 问题清单（去重+优先级排序）
   - 修改记录
   - 核对结果
   - **审查总结**：本章暴露的系统性问题模式

2. **滚动记忆注入**：每次启动新一轮审查时加载：
   - **近3章的审查总结**（重点：系统性问题模式）
   - **本章大纲+角色卡**
   - **本章正文**

3. **记忆衰减规则**：只加载近3章审查总结。系统性问题模式（跨3章以上反复出现的）写入 `reviews/patterns.md`，每次审查都加载。

**审查→修改→核对闭环**：

1. 蛋蛋收集5个视角的问题，去重并按优先级排序：
   - 🔴 P0：必须改（逻辑硬伤、信息差穿帮、角色OOC）
   - 🟡 P1：应该改（AI套话、节奏问题、伏笔遗漏）
   - 🟢 P2：建议改（文风微调、细节润色）
2. 逐项修改正文（只改P0和P1，P2视情况）
3. 核对修改：确认每个P0/P1问题已解决，且修改未引入新问题
4. 核对通过→写下一章；核对不通过→再改一轮

## 阶段5：审校（Refine）

确保全书一致性、连贯性、文学质量。

### 5.1 一致性检查
- **角色一致性**：性格/语言风格/能力是否前后统一
- **时间线一致性**：时间/季节/年龄是否矛盾
- **逻辑一致性**：因果链是否成立，有无剧情漏洞
- **世界观一致性**：规则是否前后矛盾
- **信息差一致性**：角色是否"知道"了不该知道的事

### 5.2 伏笔闭环检查
- 所有planned伏笔是否都已回收？
- 回收方式是否自然？
- 伏笔是否隐而不露？

### 5.3 文风统一润色
- 全书语言风格是否统一
- AI生成痕迹检测与消除
- 对话节奏调整
- 叙述节奏优化
- **高频意象频率检查**：同一种感官意象全文不超过5次，超过7次需删减
- **Show Don't Tell全文扫描**：搜索"感到""觉得""意识到""心中暗想""不禁""竟然"——出现一次改写一次
- **声音节奏检查**：连续3+短句需接长句喘息，连续2+长句需接短句加速
- **断行审批3问**：每个独立断行必须回答——①前文是否有3句以上铺垫？②断行内容是否角色此刻最强念头？③读者会觉得"突然冒出来"吗？
- **隐喻密织功能标注**：每段环境描写必须标注隐喻功能
- **破折号频率控制**：每1000字≤8个破折号
- **重复用词检测**：同一非锚定实词>8次需检查替换

> ⚡ 审校时，加载 `references/review-checklist.md` 获取完整检查清单。

### 5.4 精修与删减

**长篇**：斯蒂芬·金律——终稿比初稿至少短10%。**Kill Your Darlings**。

**短篇**：不机械按比例删减，标注冗余段落定向精简。

### 5.5 价值转换终检
麦基法则：逐场景检查是否有价值翻转，没有翻转的场景删或改。

### 5.6 产出
- 终稿
- 审校报告

### 5.7 审校方式

| 方式 | 适用场景 | 注意事项 |
|------|---------|---------|
| **自审** | 短篇，或所有篇幅 | 逐章检查，参照bible/outline验证一致性。**推荐** |
| **5视角逐视角自审** | 中长篇，每章写完后 | 蛋蛋在主对话中逐个输出5个视角审查 |
| **用户审阅** | 最终把关 | 提供审校报告辅助用户快速定位问题 |

⚠️ **整个审校流程禁止使用delegate_task**

**5视角全书终审流程**（全书写完后启动）：

中篇/长篇在执笔阶段已经逐章做了5视角审查+修改+核对闭环，终审做的是**全书级检查**——逐章审查做不到的跨卷问题。

**全书级检查项**：

| 视角 | 全书级检查重点 |
|-------|--------------|
| 🔍 逻辑侦探 | 跨卷逻辑链、全书信息差一致性、时间线从头到尾无矛盾 |
| 💗 情感猎手 | 角色弧线完整性、情感曲线是否有断裂、读者情绪体验是否连贯 |
| 🎭 风格鉴定师 | 全书文风统一性、AI痕迹残留、全书节奏是否有平原区/注水区 |
| 🗺️ 结构建筑师 | 全书伏笔闭环、大纲vs终稿偏离度、价值转换全覆盖 |
| 🌍 世界观守门人 | 世界观规则全书一致性、约束是否崩塌、物理定律退化是否自洽到底 |

**产出**：`reviews/final/review.md`，包含5个视角的全书级审查意见+终审修改计划
