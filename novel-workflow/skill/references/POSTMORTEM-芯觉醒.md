# 《芯觉醒》完结复盘（案例附录）

> 这是 `long-form-pitfalls.md`（通用避坑指南）的**实战案例**，记录芯觉醒 167 章写作中真实发生的事故和数据。通用方法论见 long-form-pitfalls.md，本文件提供具体教训的现场。

## 一、做对了什么（可复用经验）

1. **五阶段流程 + 确定性 checker 自闭环**——每章 `novel_check --single` exit 0 才算完成，LLM 生成 + 确定性验证器的组合可靠。这是工作流的核心，下一本保留。
2. **bible/outline/timeline/foreshadowing 四件套**——长篇没有这四个文件会崩。逐章维护，伏笔闭环靠 foreshadowing 表追踪。
3. **擦边/锚点自动化检测**——四女主身材锚点+擦边写进 config，check 自动判，避免遗漏。
4. **子 agent 并行补流程文档**——批量补审查/摘要时用并行 agent，比串行快。
5. **"从头推导"作为母题**——一个能贯穿全书的方法论 motif（不是技术细节，是价值观），让 167 章有统一魂。下一本也要找到这种"魂词"。

## 二、核心事故：脚本反复编辑导致内容错乱（最严重）

**现象**：V5-V6 阶段（约 ch120-167），为补字数/压破折号/改 motif，反复用 `python3 -c "text.replace(...)"` 或 heredoc 编辑整章文件。

**后果**：
- **31 章出现整段复制**（描写/对话段落被复制 2-4 次），最严重 ch155 删了 18 段
- 约 90 个重复段落，是真正的内容损坏，不是风格问题
- 直到用户问"会不会存在多次编辑导致内容错乱"才被发现——check 没抓到

**根因**：
- check 只检测句子级重复（≥5次），整段复制时段内单句可能只出现 2-4 次，逃过检测
- replace 基于内存旧文本，append 内容到结尾时容易重复
- 为凑字数机械追加，没控制内容的实质性

**修复（已落地）**：
- ✅ `novel_check.py` 新增 **2.6b 段落级重复检测**：整段≥15字出现≥2次即判不合格。上线后立刻抓到 2 处（ch95/ch162）人工清理遗漏的。
- ✅ SKILL.md 执笔阶段新增铁律：禁止用脚本反复 replace 补字数，必须用 Write/Edit 一次写到位。

## 五、一句话教训

> **字数不够是内容问题，不是数字问题。** 用脚本往结尾堆排比凑到 2850，等于没写。check 是质量底线，不是质量本身——过了 check 不等于写得好，但过不了 check 一定不合格。下一本：一次写到位，一章一结，别攒批，别用脚本 replace 整章。
