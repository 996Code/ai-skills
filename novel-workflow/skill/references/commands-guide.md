# 蛋蛋小说工作流 — 命令使用手册

> 9个命令，覆盖从"一个念头"到"一本书完结"的全流程。这份手册帮你快速上手。

---

## 一、命令总览

```
📕 /new-novel    开新书（初始化项目）
🎬 /prospect     探矿（从模糊想法到清晰创意）
🗺️ /build-world  构筑（世界观+角色+规则）
📋 /plan-story   谋篇（可执行的故事大纲）
✍️ /write-chapter 执笔（逐章写作，自带质量铁律）
🔍 /check        质量检查（单章/全量）
🔍 /refine       审校（全书一致性+质量保证）
🔄 /resume       恢复进度（跨会话快速定位）
📧 /send-novel   发送小说到邮箱
```

---

## 二、一张图看懂流程

```
开新书          /new-novel
  │
  ▼
探矿阶段        /prospect ──── 想清楚"写什么"
  │
  ▼
构筑阶段        /build-world ── 建好"世界和人物"
  │
  ▼
谋篇阶段        /plan-story ─── 画好"施工图"
  │
  ▼
执笔阶段        /write-chapter ─ 一章一章写（每章写完跑 /check）
  │                           ↗
  │             /check ──────┘  检查质量，不过就改
  │
  ▼
审校阶段        /refine ─────── 全书检查，修一致性
  │
  ▼
交付            /send-novel ─── 发到邮箱
```

**铁律**：必须按顺序走，不能跳步。每个阶段是下一阶段的基础。

| 你的情况 | 用哪个命令 |

## 四、每个命令详解

### 📕 /new-novel — 开新书

**什么时候用**：创意基本确定，要正式开始一个新项目。

**它会做什么**：
1. 检查有没有未完结的旧书（确认是从0开始还是另起新项目）
2. 创建项目目录结构（`novels/小说名/text/ planning/ summaries/ reviews/`）
3. 初始化配置文件（女主锚点、motif词表、五感词等）
4. 提示你进入探矿或构筑

**用法**：
```
/new-novel 我想写一本重生都市商战小说
```

**注意**：如果是"从0开始"且创意变了，旧项目目录会被删除/重命名。

---

### 🎬 /prospect — 探矿

**什么时候用**：有一个模糊的念头，还没想清楚写什么。

**它的角色**：创作搭档，不是写作工具。它会像朋友一样和你聊天，帮你把念头变成清晰的创意。

**它会问你**：
- 一句话讲什么故事？
- 主角是谁？想要什么？
- 核心冲突是什么？
- 爽点是什么？（网文最重要的）
- 情绪基调？（搞笑/热血/虐心/治愈）

**用法**：
```
/prospect 我想写一个程序员重生回到大学的故事
```

**产出**：创意简报（creative-brief），写清"写什么"。

---

### 🗺️ /build-world — 构筑

**什么时候用**：创意清楚了，要建世界观和角色。

**它会做什么**：
1. **世界观**：时代/地点/规则/禁忌
2. **角色 bible**：主角弧线、配角性格、反派动机
3. **timeline**：故事前的背景事件
4. **foreshadowing**：埋伏笔，标注回收章

**关键认知**：世界观不是百科全书，是写作时的约束。只写故事会用到的设定。

**用法**：
```
/build-world
```

**产出**：bible 四件套（characters/world/timeline/foreshadowing）。

---

### 📋 /plan-story — 谋篇

**什么时候用**：世界观建好了，要画"施工图"。

**它会做什么**：
1. **总纲**：全书一句话概括、主角弧线、卷划分、三幕节拍
2. **卷纲**：每卷的核心任务、情绪曲线、四阶段结构
3. **逐章细纲**：每章3个场景，每个场景写清内容/角色/目的/钩子/情绪

**铁律**：
- 每卷开写前必须确认大纲齐全（大纲没写到本卷末章，不开写）
- 每章必须有钩子（绝境/转机/悬念/情感临界/反转）
- 黄金三章：前3章必须有强钩子（网文生死线）

**用法**：
```
/plan-story
```

**产出**：总纲 + 卷纲 + 逐章细纲。

---

### ✍️ /write-chapter — 执笔

**什么时候用**：大纲齐了，开始写正文。这是用得最多的命令。

**它的核心价值**：自带质量铁律，写的时候就控制好指标，避免写完返工。

**写作铁律**（违反=返工）：
1. **一次写到位**：目标2900±100字，不要写1500再补
2. **禁止脚本补字数**：不要用python反复replace（会导致内容损坏）
3. **禁止堆排比凑字数**：字数不够=内容不足，加实质场景
4. **写时控指标**：破折号少用、motif词≤15次、避开SDT违禁词
5. **四女主锚点**：出场就要有身材锚点+擦边
6. **五感≥3**：不能只写视觉

**写完后的闭环**（一章一结）：
1. 跑 `/check`（迭代到 exit 0）
2. 写6视角审查文件
3. 写章节摘要
4. 更新 timeline/foreshadowing

**用法**：
```
/write-chapter 写第130章
```

---

### 🔍 /check — 质量检查

**什么时候用**：写完一章想检查，或想看全书质量。

**用法**：
```bash
# 单章检查（最常用）
python3 scripts/novel_check.py --single "novels/小说名/text/第130章：标题.txt"

# 全量检查
python3 scripts/novel_check.py
```

**它检查什么**（硬指标）：
| 指标 | 标准 |
|------|------|
| 字数 | 2850-3150 |
| SDT违禁词 | 0个（感到/觉得/意识到等） |
| 重复段落 | 0处（整段复制会被抓） |
| motif密度 | 母题词不超标 |
| 破折号 | ≤9.5/千字 |
| 五感 | ≥3种 |
| 女主锚点/擦边 | 出场就要有 |

**check不过怎么办**：
- 字数不足 → 重写补实质内容（不要堆排比）
- 破折号超标 → 把——改成逗号
- motif超标 → 用同义词替换

---

### 🔍 /refine — 审校

**什么时候用**：全书写完后，做最后的全书级检查。

**它做什么**（和逐章检查不同，这是跨章/全书级）：
1. **一致性检查**：角色性格/时间线/逻辑/世界观前后统一？
2. **伏笔闭环**：所有伏笔都回收了吗？
3. **文风统一**：SDT扫描、高频意象、破折号频率
4. **质量深检**：跑全量 check
5. **精修删减**：去冗余（终稿比初稿短10%）

**用法**：
```
/refine
```

---

### 🔄 /resume — 恢复进度

**什么时候用**：开了新会话（比如第二天继续），要快速恢复到昨天的进度。

**它会做什么**：
1. 看git log确认项目名和进度
2. 读文件（不翻对话历史）确认写到第几章
3. 加载bible/outline/timeline
4. 告诉你下一步该做什么

**铁律**：不翻对话历史（太长会溢出上下文）。靠文件恢复。

**用法**：
```
/resume
```

---

### 📧 /send-novel — 发送到邮箱

**什么时候用**：正文定稿，想发到邮箱看。

**它会做什么**：交付前必检（无格式残留/SDT通过/破折号达标），然后发邮件。

**用法**：
```
/send-novel
```

## 五、典型工作流（从0到完结）

### 场景1：从零开始写一本新书
```
/new-novel          → 初始化项目
/prospect           → 把创意想清楚
/build-world        → 建世界观和角色
/plan-story         → 画大纲
/write-chapter      → 写第1章
/check              → 检查第1章
/write-chapter      → 写第2章
/check              → 检查第2章
...（重复写+检查）...
/refine             → 全书写完，终审
/send-novel         → 发邮件
```

### 场景2：第二天接着写
```
/resume             → 恢复进度（看到写到第50章）
/write-chapter      → 继续写第51章
/check              → 检查
```

### 场景3：检查某一章质量
```
/check              → 跑单章检查
（如果不过）直接修改 → 再 /check
```

### 场景4：批量写多章
```
/write-chapter      → 写第130章（写完跑check+审查+摘要，一章一结）
/write-chapter      → 写第131章
/write-chapter      → 写第132章
...
```
**注意**：每章写完必须当章闭环（check+审查+摘要），不要攒批。

## 六、避坑速记（每条都是实战教训）

1. **不要用脚本补字数** → 会导致整段复制，内容损坏
2. **不要堆排比凑字数** → 字数不够=内容不足，加实质场景
3. **不要跳阶段** → 大纲没齐就开写，写到一半必崩
4. **不要攒批补流程文档** → 一章一结，当章完成审查/摘要/timeline
5. **check是底线不是质量** → 过了check≠写得好，但过不了一定不合格
6. **不翻历史对话** → 用 /resume 读文件恢复，历史太长会溢出

## 七、核心文件结构（写完一本后长这样）

```
novels/小说名/
├── 简介.txt                    ← 封底简介
├── text/                       ← 正文（第N章：标题.txt）
├── planning/
│   ├── bible/
│   │   ├── characters/         ← 角色 bible
│   │   ├── world/              ← 世界观
│   │   ├── timeline.md         ← 时间线
│   │   ├── foreshadowing.md    ← 伏笔追踪
│   │   └── quick-ref.md        ← 速查
│   └── outline/
│       ├── overview.md         ← 总纲
│       ├── volumes/            ← 卷纲
│       └── chapters/           ← 逐章细纲
├── summaries/                  ← 章节摘要
├── reviews/per-chapter/        ← 逐章审查（6视角）
└── novel-config.json           ← 配置（锚点/motif/五感）
```
