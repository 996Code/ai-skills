# AI长篇小说一致性技术方案

> 整理时间：2026年5月 | 整理人：蛋蛋 | 来源：网络调研+技术分析

---

## 1. 向量数据库(RAG)在小说创作中的应用

### 分块策略
- **语义分块**：按场景/段落边界切分，推荐500-1000 tokens，重叠100-200 tokens
- **层级分块**：同时存储章节级摘要（粗粒度）和段落级原文（细粒度）
- **元数据标注**：章节号、涉及角色、时间线位置、场景类型、情感基调

### 向量数据库选型
- **ChromaDB**：轻量级，适合个人项目，支持元数据过滤
- **LanceDB**：嵌入式设计，适合本地部署
- **Milvus/Pinecone**：生产级，大规模检索

### 检索策略
- **混合检索**：向量相似度 + BM25关键词检索结合
- **元数据过滤**：生成第N章时，只检索第1到N-1章的内容
- **角色锚定检索**：提到某角色时，自动检索其所有历史出场片段
- **时间线约束检索**：按故事内时间排序

## 2. 章节摘要链（递归摘要）

### 四层结构
- **L0**: 原文（完整章节文本）
- **L1**: 单章摘要（每章200-300字，结构化JSON）
- **L2**: 卷/弧摘要（每5-10章合并，500-800字）
- **L3**: 全书摘要（整体故事线，1000-2000字）

### 滑动窗口摘要
```
上下文窗口 = [第N-2章摘要] + [第N-1章摘要] + [第N章原文] + [写作指令]
```

### 事件图谱摘要
将摘要结构化为事件序列，每条事件包含：id、类型、描述、涉及角色、章节、是否已解决

---

## 3. 角色状态追踪

### 动态状态卡
每个角色维护：基础特质 + 动态状态（位置/情绪/知识/关系/物品/身体） + 弧线进度

### 状态更新机制
1. 每章生成后，用LLM提取角色状态变化
2. 将变更merge到角色档案
3. 冲突检测：新状态与已有状态矛盾时标记需人工审核

### 信息隔离
严格区分"角色知道什么"vs"读者知道什么"vs"作者知道什么"

---

## 4. 伏笔管理自动化

### 伏笔追踪数据库
每条伏笔包含：id、埋设章节、类型(mystery/promise/symbol/omen)、重要程度、预期回收章节、状态(planted/hinted/resolved/abandoned)、中间暗示章节、回收描述

### 自动化流程
- **埋设检测**：每章生成后LLM扫描识别潜在伏笔
- **回收提醒**：生成新章节前检查待回收伏笔
- **一致性校验**：检测意外回收和超期未回收

## 5. 上下文窗口分配策略

### 128K上下文分配建议
```
系统指令 + 风格指南      ~2K
全书摘要(L3)             ~2K
当前卷摘要(L2)           ~2K
近3章摘要(L1)            ~3K
角色状态卡(相关角色)      ~3K
伏笔状态(待回收)         ~1K
RAG检索结果              ~5K
当前章节已写内容          ~10K
写作指令                 ~0.5K
────────────────────────────
预留生成空间             ~99.5K
```

### 压缩技术
- 渐进式上下文：距离越远信息越压缩
- 动态组装：按需加载，不每章加载全部
- Prompt Caching：固定前缀缓存，减少50-90%消耗

## 6. 推荐技术架构

```
用户输入指令
     ↓
规划Agent ← 全书大纲 + 当前卷摘要
     ↓
上下文组装器
  - 角色状态(相关角色)
  - 伏笔提醒(待回收)
  - RAG检索(相关历史片段)
  - 近章摘要(滑动窗口)
     ↓
写作Agent → 生成章节内容
     ↓
后处理流水线
  - 章节摘要生成(L1)
  - 角色状态提取与更新
  - 伏笔埋设/回收检测
  - 向量库入库(chunks)
  - 一致性校验
```

### 核心项目文件结构
```
novel_project/
├── outline/           # 大纲（总纲+卷纲+章纲）
├── chapters/          # 章节原文
├── summaries/         # 摘要链（L1/L2/L3）
├── characters/        # 角色状态卡+关系图谱
├── foreshadowing/     # 伏笔追踪
├── vector_db/         # 向量数据库
├── events/            # 事件时间线
└── config/            # 风格指南+世界观设定
```

### 最值得参考的开源项目
- **MemGPT/Letta** — 最成熟的长文本记忆管理框架，分层记忆+自动检索，**最推荐**
- **LangChain/LlamaIndex** — 通用RAG框架，LlamaIndex的SummaryIndex适合章节摘要链
